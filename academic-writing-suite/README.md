# academic-writing-suite

Комплекс из оркестратора и шести субагентов для написания разделов ВКР, статей
и учебных материалов по железнодорожной автоматике и телемеханике (СЦБ) — в
подтверждённом идиолекте автора. Текст проходит конвейер
`research → calc → draft → humanizer → norm-control` с факт-замком, иерархией
правил стиля и детерминированной проверкой на AI-маркеры.

Один триггер `/academic-writing-suite` маршрутизирует запрос к нужному
субагенту; один `install.sh` ставит suite в 15 инструментов (Claude Code,
OpenCode, Cursor, Copilot и др.).

## Возможности

- **Оркестратор** — декомпозирует запрос и вызывает профильных субагентов,
  пользователю возвращается только результат последнего шага конвейера.
- **Шесть субагентов** — research (факты и цитаты), calc (проверяемые расчёты
  по нормативам, JSON-контракт вывода), draft (черновик по IMRAD в идиолекте),
  humanizer (обязательный гейт очеловечивания), norm-control (ссылки и
  ГОСТ 7.32-2017), style-calibrator (обучение на правках автора).
- **Факт-замок** — числа, даты, имена, номера ГОСТов и проценты переносятся из
  источников без искажений на каждом шаге; нет данных → маркер пробела, а не
  правдоподобная выдумка.
- **Идиолект автора** — `assets/user-idiolect.md` с правилами частотой ≥ 3/7 и
  калибровочный цикл: черновик → правка автора → style-calibrator → новые
  правила для draft-agent.
- **Детерминированные evals** — 7 command-чеков (AI-маркеры, бэктики,
  риторические вопросы, кавычки-ёлочки и др.) + 2 LLM-judge-чека с канарейкой,
  5 golden cases. Всё гоняется stdlib-скриптом без внешних зависимостей.
- **Кроссплатформенная установка** — один установщик для Claude Code, OpenCode,
  Copilot, Cursor, Windsurf, Cline, Codex, Gemini, Kiro, Trae, Goose, Roo Code,
  Kilo Code, Factory, Junie, Antigravity.

## Как это работает

Запрос «напиши раздел 2.1.1» проходит по конвейеру; каждый субагент получает
самодостаточный промпт (дословный заголовок, пути файлов, полный вывод
предыдущего шага) — субагенты не видят историю диалога:

```
                 ┌────────────────────────────────────────────────┐
   «напиши       │ research-agent    ─┐  параллельно              │
   раздел 2.1.1» │ calc-agent        ─┘  (если есть числа/формулы)│
      │          │ draft-agent   (IMRAD, читает user-idiolect.md) │
      └────────► │ humanizer-agent  (обязательный гейт, эм-деши)  │
                 │ norm-control-agent  (ссылки [N], ГОСТ — маркер)│
                 └────────────────────────────────────────────────┘
                              │
                              ▼
                   финальный текст раздела
```

Другие триггеры маршрутизируются напрямую:

| Запрос | Куда уходит |
|---|---|
| «проверь текст на AI-маркеры» | humanizer-agent, режим `audit` (помечает, не переписывает) |
| «пересчитай межпоездной интервал» | calc-agent (формула + исходные данные + результат) |
| «сравни черновик и мою правку» | style-calibrator-agent (дифф → категории → порог 3+ → user-idiolect) |

### Карта субагентов

| Субагент | Роль | Когда вызывать |
|---|---|---|
| research-agent | сбор фактов, цифр и цитат из файлов Space и веба | «напиши раздел», «собери материал» — первым |
| calc-agent | проверяемые расчёты по нормативным методикам | параллельно с research, если есть числа |
| draft-agent | черновик по IMRAD, читает идиолект автора | после research/calc, до humanizer |
| humanizer-agent | очеловечивание, факт-замок, эм-деши ≤ 3–5 % | всегда после draft, до norm-control |
| norm-control-agent | ссылки [N], термины, ГОСТ 7.32-2017 — только помечает | перед выдачей финального текста |
| style-calibrator-agent | дифф пары → категории → порог 3+ → user-idiolect | только по «сравни черновик и мою правку» |

### Иерархия правил

При конфликте правил применяется порядок: **факт-замок** → **подтверждённый
`assets/user-idiolect.md`** (частота ≥ 3/7) → **каталог humanizer** (33
академических паттерна + русская механика) → **общие стилевые правила Space**.

> [!NOTE]
> Границы полномочий: humanizer-agent — финальная инстанция по стилю, его
> правка не пересматривается; norm-control-agent имеет право только помечать
> ссылки и терминологический разнобой, но не переписывать стиль повторно —
> иначе конвейер «пинг-понгует» между субагентами на одном абзаце.

## Требования

- Python 3.11+ (только стандартная библиотека; нужен для evals и скриптов
  обслуживания — для работы субагентов не требуется)
- Один из поддерживаемых ИИ-инструментов (Claude Code, OpenCode и др.)

## Установка

### Claude Code (родной плагин-путь)

```bash
/plugin marketplace add ./academic-writing-suite
/plugin install academic-writing-suite
```

### Остальные платформы (универсальный установщик)

```bash
./install.sh                # автоопределение платформы, user-level
./install.sh --project      # project-level (текущая директория)
./install.sh --platform opencode --path ~/.config/opencode/skills/
./install.sh --all          # установить во все обнаруженные инструменты
./install.sh --dry-run      # предпросмотр без изменений
```

### Вручную

| Платформа | Путь |
|---|---|
| Claude Code | `~/.claude/skills/academic-writing-suite/` |
| OpenCode | `~/.config/opencode/skills/academic-writing-suite/` |
| Codex / универсальный | `~/.agents/skills/academic-writing-suite/` |
| Gemini CLI | `~/.gemini/skills/academic-writing-suite/` |
| Cursor (адаптация `.mdc`) | `~/.cursor/rules/academic-writing-suite.mdc` |

Скопируйте содержимое пакета (SKILL.md, AGENTS.md, skills/, shared/, assets/,
references/, evals/, .claude-plugin/) в выбранный путь.

## Использование

```
/academic-writing-suite напиши раздел 2.1.1 Постановка задачи формализации
/academic-writing-suite проверь текст на AI-маркеры
/academic-writing-suite рассчитай межпоездной интервал
/academic-writing-suite сравни черновик и мою правку
```

> [!TIP]
> Перед полным развёртыванием прогоните архитектуру на 2–3 реальных разделах
> ВКР: конвейер увеличивает число вызовов модели на раздел, а рассинхронизация
> форматов между шагами (например, calc-agent вернёт цифру без единиц
> измерения) ломает следующий шаг.

## Калибровка идиолекта

1. draft-agent пишет черновик, автор вручную правит текст.
2. Автор запускает «сравни черновик и мою правку» — style-calibrator-agent
   строит дифф по предложениям (`shared/diff_texts.py`), классифицирует правки.
3. Правила, повторившиеся ≥ 3 раз из 7 проверок, попадают в
   `assets/user-idiolect.md` и становятся обязательными для draft-agent.

## Структура проекта

```
academic-writing-suite/
├── SKILL.md                  # оркестратор: маршрутизация, протокол делегирования
├── AGENTS.md                 # краткое описание для агентов
├── install.sh                # кроссплатформенный установщик (15 инструментов)
├── skills/                   # 6 субагентов, по SKILL.md на каждого
│   ├── research-agent/
│   ├── calc-agent/
│   ├── draft-agent/
│   ├── humanizer-agent/
│   ├── norm-control-agent/
│   └── style-calibrator-agent/
├── shared/                   # инструменты субагентов (stdlib, без зависимостей)
│   ├── diff_texts.py         # дифф по предложениям
│   ├── rhythm_metrics.py     # доля эм-дешей, ритм, AI-маркеры
│   └── eval_checks.py        # детерминированные чек-функции для evals
├── assets/                   # user-idiolect.md (подтверждённые правила), candidates.md
├── evals/                    # спецификация evals + 5 golden cases
├── references/               # справочные материалы (idiolect-guide.md и др.)
├── scripts/                  # обслуживание: run_evals.py, evolve.py, staleness...
└── .claude-plugin/           # метаданные для Claude Code marketplace
```

## Тестирование и обслуживание

Из корня suite:

```bash
python3 scripts/run_evals.py --validate        # проверить спецификацию (должна быть VALID)
python3 scripts/run_evals.py                   # command-чеки по golden-бейзлайну
python3 scripts/run_evals.py --rollout --judge # judge-чеки (связность, тон) с канарейкой
python3 scripts/evolve.py                      # staleness + evals одним запуском
python3 scripts/evolve.py --correct "<что пошло не так>"  # зафиксировать правку в EVOLUTION.md
```

Состояние: 18/18 command-чеков зелёные при `python -W error`, case-3 —
holdout, case-5 — pending-first-green (канарейка не применима).
