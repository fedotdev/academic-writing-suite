## [1.5.6] — 2026-08-25 — рестарт нумерации списков; сломанные заголовки

### Добавлено
- `scripts/fix_docx_numbering.py` — пост-процесс сборки DOCX:
  - каждая непрерывная группа пунктов стилей `a7` («Нумерованный одноуровневый
    список») и `aa` («Нумерованный список без точки») получает СВОЙ `numId`
    (все numId ссылаются на один abstractNum формата стиля; каждый numId
    ведёт независимый счётчик). Без этого Word нумеровал списки непрерывно по
    всему документу: первый пункт очередного списка показывал «7)», «15)»
    вместо «1)» (наблюдалось: «7) Максимальная разрешенная скорость» в
    разделе 1.1 — продолжение нумерации со списка задач введения);

    (abstractNum 7/10 из reference: формат «%1)» и «%1»), которые pandoc не
    переносит из шаблона — иначе стилям вообще не на что ссылаться;
  - добавлен в конвейер сборки в SKILL.md SCRIPT USAGE (после fix_table.py).
- `scripts/document_style_validator.py`: (в 1.5.5) DOCX-чек
  `structural-element-wrong-style` — параграфы АННОТАЦИЯ, СОДЕРЖАНИЕ, ВВЕДЕНИЕ,
  ЗАКЛЮЧЕНИЕ, СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ обязаны иметь styleId `7322`.
  Сами div не распознавались pandoc без пустых строк вокруг «:::».

## [1.5.5] — 2026-08-25 — валидатор: структурные элементы (7322); дубль подписи рисунка

  ИСТОЧНИКОВ обязаны иметь styleId `7322` («Структурный элемент обязательный
  7.32»). Ранее валидатор DOCX этого не проверял: сломанные div давали
  Normal/Body Text без единой ошибки. Self-check расширен (good docx со стилем
  7322 проходит; bad docx с «ВВЕДЕНИЕ» в Normal падает).

### Исправлено
- `full-doc-2026-08-22/final/vkr_full.md` — причина «::: ... не работает»:
  - **ВВЕДЕНИЕ**: после `**СОДЕРЖАНИЕ**` и вокруг div не было пустых строк —
    pandoc не распознавал fenced div (та же причина, что со списком источников
    в 1.5.4). Пустые строки добавлены;
  - **ЗАКЛЮЧЕНИЕ** и **СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ**: div открывался
    сразу после текстовой строки (один `\n`) — добавлены пустые строки;
  - **АННОТАЦИЯ** и **СОДЕРЖАНИЕ**: были `**жирным**` текстом без div —
    обёрнуты в `::: {custom-style="Структурный элемент обязательный 7.32"}`.
  - Рисунок 1.1: подпись была **alt-текстом встроенного изображения**
    (`![Рисунок 1.1 --- …](media/image2.svg)`); при отсутствии файла pandoc
    заменял её описанием ДВАЖДЫ (таблица-обёртка + ImageCaption) — дубль в
    DOCX. Приведён к стандартной схеме: `![](media/image2.svg)` + подпись в
    div `::: {custom-style="caption"}`.
- Итог: `vkr_full.md` — MD-валидатор [OK] PASSED; пересобранный DOCX (18 таблиц
  → `12pt`, 8 пустых абзацев после подписей) — DOCX-валидатор [OK] PASSED;

## [1.5.2] — 2026-08-22 — artifact_store: кириллица и LF на Windows (корневой фикс)

### Исправлено
- `scripts/artifact_store.py --save` читал содержимое только из stdin; при
  вызове через PowerShell-пайп (`Get-Content -Raw | python ...`) текст
  приходил в OEM-кодировке (cp866) и артефакт портился (в прогоне главы 3
  дважды затирал черновики до нечитаемых «кракозябр»).
  Добавлен флаг **`--file <src>`** — читает содержимое прямо из файла
  (`_read_text_any_encoding`: utf-8-sig → utf-8 → cp866 → cp1251, нормализация
  в чистый UTF-8; пересохраняет исходник в канонический UTF-8). Рекомендуемый
  вызов: `artifact_store.py --save <path> --file <src> --kind ... --index ...`
  (субагент пишет файл Write-инструментом, затем регистрирует через `--file`).
- `shared/v3.py atomic_write`: text-mode Windows по умолчанию пишет `\r\n`,
  что ломало канонический LF и sha256-контракт артефактов. Явно задан
  `newline="\n"` — файлы теперь всегда LF.
- stdin-путь сохранён для совместимости, но при чтении используется
  буферизованный байтовый поток (UTF-8), а не консольная кодировка.

### Проверено
- `scripts/test_v3.py` — ВСЕ ПРОВЕРКИ ПРОШЛИ (включая контракты §9).
- `artifact_store.py --selfcheck` — атомарность, sha256, уникальность index,
  кодировка.
- Живой тест `--file`: cp866-файл (сломанный пайп) нормализуется в UTF-8,
  index идемпотентен, LF-контракт соблюдён.

## [1.3.0] — 2026-08-15

### Добавлено
- `scripts/document_style_validator.py` — детерминированный валидатор DOCX и markdown-источников, проверяет 5 контрактов:
  1. Заголовки: без литеральных номеров, без пустых скобок, автоматическая нумерация через многоуровневый список
  2. Уровни: N.M.K только где предусмотрено, без пропусков уровней
  3. Формулы: без юникодных подстрочных символов (U+2080–U+209C) вне LaTeX, keepLines для выносных
  4. Подписи: рисунки/таблицы в стиле `caption` (aff), без дублирования
  5. Список источников: 100% пунктов в стиле `Нумерованный список без точки` (aa)
- Режимы работы: `--docx` (по умолчанию), `--md` (проверка markdown до сборки), `--self-check`
- Выход: `outputs/audit-report.md` с детальным списком нарушений
- Интеграция в экспорт: `python scripts/document_style_validator.py outputs/thesis.docx` после pandoc

### Изменено
- **Template surgery**: `Normal_GOST-7-32-2017.dotm` — стили `heading 1/2/3` теперь наследуют нумерацию (numId=24, ilvl=0/1/2) и форматирование от GOST-стилей `Заголовок раздела/подраздела/пункта`
- **Template surgery (fix Word error)**: перезапись styles.xml с сохранением оригинального корневого тега —
  все `xmlns:*` и `mc:Ignorable` объявления остаются нетронутыми (ET.tostring выкидывал неиспользуемые
  префиксы, и Word ругался на необъявленные префиксы в `mc:Ignorable`); элементы `pPr` вставляются
  в строгом порядке OOXML-схемы
- Удалён `--number-sections` из команды pandoc в SKILL.md и README.md — нумерация осуществляется исключительно многоуровневым списком шаблона
- Удалена `-f markdown-implicit_figures` — подписи рисунков формируются явно через div `::: {custom-style="caption"}`, без дублирования из alt-текста
- Контракт рисунков: одна строка с пустым alt `![](placeholder.png)`, подпись отдельным абзацем в div со стилем `caption`
- Контракт формул: запрещены юникодные подстрочные символы (U+2080–U+209C) вне LaTeX, только `$I_{k}$` / `$u_{оп}$`
- Контракт списка источников: **обязательное** оборачивание в div `::: {custom-style="Нумерованный список без точки"}`, свободные абзацы запрещены
- Уровни заголовков: явно документированы N (глава), N.M (подраздел), N.M.K (пункт) — третий уровень по необходимости

### Исправлено
- Дефект #1: дублирование номеров заголовков (1.1 1.1) — pandoc больше не пишет литеральные номера, нумерация только из стиля
