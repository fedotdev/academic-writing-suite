# Идиолект автора: как читать и обновлять

Правила идиолекта — это «письмо агента»: подтверждённый стиль конкретного
автора, который draft-agent обязан применять с приоритетом выше общих стилевых
инструкций.

## Где лежат файлы

- `assets/user-idiolect.md` — **seed**: подтверждённые правила (частотой ≥ 3/7)
  из первого прогона калибровки (7 пар, 17 операций, дифф 2026-08-14).
- `assets/candidates.md` — **seed**: правила с частотой 1–2/7, не применять до
  3-го вхождения.
- Рабочая копия для накопления живёт обычно в `style-calibration/` рядом с
  проектом; при первом запуске style-calibrator-agent копирует seed в рабочую
  папку и дальше обновляет только её.

## Кто читает

- **draft-agent** — читает `assets/user-idiolect.md` (или рабочую копию) перед
  каждой генерацией; применяет только подтверждённые правила, `candidates.md`
  не применяет.
- **style-calibrator-agent** — единственный, кто пишет/обновляет файлы: дифф
  пар «черновик → правка», классификация операций, агрегация с порогом 3+.

## Формат правила

```
### Правило: <императив, что делать>
Частота: <N/всего пар>
Добавлено: <YYYY-MM-DD>
Ревизия: <целое, растёт при изменении>
Пример:
  До: "<фрагмент черновика>"
  После: "<фрагмент правки>"
Инструкция для draft-agent: <прямая инструкция писателю>
```

## Правила обновления

1. **Порог 3+**: правило переезжает из `candidates.md` в `user-idiolect.md`
   только при 3-м вхождении в истории `edit-log.jsonl`. Одно-два вхождения —
   гипотеза, не правило.
2. **Императив**: формулировка — инструкция писателю («не выделять жирным»,
   «в курсиве»), а не наблюдение («автор чаще использует курсив»).
3. **Версионирование**: при каждом изменении правила ревизия растёт на 1;
   частота и дата добавления обновляются. При 20–30+ парах правила с ревизией
   > 3 и нулевыми новыми вхождениями пересматриваются на актуальность (стиль
   автора может меняться).
4. **Приоритет**: идиолект (≥3/7) стоит выше каталога humanizer-agent и общих
   правил Space, но ниже факт-замка (числа/ГОСТы не искажаются ничем).

## Советы для новых пар

- Собирайте пары «AI-черновик → ручная правка» по одному разделу за раз — на
  первой паре всё помечается кандидатами, устойчивый идиолект собирается за
  несколько циклов «черновик → правка → калибровка → новый черновик».
- Не редактируйте `user-idiolect.md` руками мимо калибратора — тогда ревизии и
  частота расходятся с `edit-log.jsonl`, и порог 3+ перестаёт работать.
