# academic-writing-suite

Комплекс из оркестратора и семи субагентов для написания разделов ВКР, статей
и учебных материалов по железнодорожной автоматике и телемеханике (СЦБ) — в
подтверждённом идиолекте автора. Поддерживает как написание отдельных разделов,
так и генерацию полного документа (главы/ВКР/статьи целиком) с автоматической
сборкой в `output/`. Текст проходит конвейер
`research → calc → draft → humanizer → norm-control` с факт-замком, иерархией
правил стиля и детерминированной проверкой на AI-маркеры.

Один триггер `/academic-writing-suite` маршрутизирует запрос к нужному
субагенту; один `install.sh` ставит suite в 16 платформ (Claude Code, OpenCode,
Cursor, Copilot и др.) + универсальный путь.

> [!NOTE]
> **Основной продукт — агент** (папка `academic-writing-suite/`). Всё остальное
> в репозитории — личные рабочие данные автора (калибровка стиля): они
> исключены из git и не публикуются. Рядовому пользователю они не нужны.

## Возможности

- **Оркестратор** — декомпозирует запрос и вызывает профильных субагентов.
  Поддерживает два режима: написание отдельных разделов (возврат в чат) и
  генерация полного документа (запись в `output/`).
- **Семь субагентов** — doc-planner (планирование структуры документа),
  research (факты и цитаты из Projects и веба), calc (проверяемые расчёты по
  нормативам, JSON-контракт вывода), draft (черновик по IMRAD в идиолекте +
  плейсхолдеры рисунков), humanizer (обязательный гейт очеловечивания),
  norm-control (ссылки, ГОСТ 7.32-2017, структура документа),
  style-calibrator (обучение на правках автора).
- **Полный документ** — запрос «напиши главу N» или «напиши весь диплом»
  запускает последовательный конвейер по всем разделам без ручной команды
  «продолжай». Результат записывается в `output/` (per-section MD + финальный
  `thesis.md`). После подтверждения MD — экспорт в DOCX через pandoc с
  шаблоном `references/Normal_GOST-7-32-2017.dotm` (оформление по ГОСТ 7.32-2017).
- **Плейсхолдеры рисунков** — draft-agent вставляет `![Рисунок N.M — описание]`
  двумя строками (markdown-image + подпись ПОД рисунком по ГОСТ 6.5.7), логирует
  в `assets/figures-todo.md`. Нумерация N.M — в пределах раздела (по ГОСТ 6.5.6).
- **Факт-замок** — числа, даты, имена, номера ГОСТов и проценты переносятся из
  источников без искажений на каждом шаге; нет данных → маркер пробела, а не
  правдоподобная выдумка.
- **Идиолект автора** — `academic-writing-suite/assets/user-idiolect.md` с
  правилами частотой ≥ 3/7 и калибровочный цикл: черновик → правка автора →
  style-calibrator → новые правила для draft-agent.
- **ГОСТ-правила** — встроенные выдержки из ГОСТ 7.32-2017 и ГОСТ 7.0.100-2018
  в `references/` для проверки оформления рисунков, таблиц, формул, ссылок.
- **Детерминированные evals** — 9 command-чеков (AI-маркеры, бэктики,
  риторические вопросы, кавычки-ёлочки, формат плейсхолдеров рисунков,
  подпись под рисунком, нумерация N.M и др.) + 2 LLM-judge-чека с канарейкой,
  6 golden cases. Всё гоняется stdlib-скриптом без внешних зависимостей.
- **Кроссплатформенная установка** — один установщик для Claude Code, model service,
  Copilot, Cursor, Windsurf, Cline, Codex, Gemini, Kiro, Trae, Goose, Roo Code,
  Kilo Code, Factory, Junie, Antigravity + универсальный путь (`universal`).

## Как это работает

Запрос «напиши раздел 2.1.1» проходит по конвейеру; каждый субагент получает
самодостаточный промпт (дословный заголовок, пути файлов, полный вывод
предыдущего шага) — субагенты не видят историю диалога:

```
                 ┌────────────────────────────────────────────────┐
   «напиши       │ research-agent    ─┐  параллельно              │
   раздел 2.1.1» │ calc-agent        ─┘  (если есть числа/формулы)│
      │          │ draft-agent   (IMRAD, читает user-idiolect.md) │
      └────────► │ humanizer-agent  (обязательный гейт, эм-деши)  │
                 │ norm-control-agent  (ссылки [N], ГОСТ — маркер)│
                 └────────────────────────────────────────────────┘
                              │
                              ▼
                   финальный текст раздела
```

Другие триггеры маршрутизируются напрямую:

| Запрос | Куда уходит |
|---|---|
| «проверь текст на AI-маркеры» | humanizer-agent, режим `audit` (помечает, не переписывает) |
| «пересчитай межпоездной интервал» | calc-agent (формула + исходные данные + результат) |
| «сравни черновик и мою правку» | style-calibrator-agent (дифф → категории → порог 3+ → user-idiolect) |

### Карта субагентов

| Субагент | Роль | Когда вызывать |
|---|---|---|
| doc-planner | планирование структуры документа | «напиши главу N», «напиши диплом» — принимает план пользователя или предлагает свой |
| research-agent | сбор фактов, цифр и цитат из файлов Projects и веба | «напиши раздел», «собери материал» — первым в конвейере |
| calc-agent | проверяемые расчёты по нормативным методикам | параллельно с research, если есть числа |
| draft-agent | черновик по IMRAD, читает идиолект автора, вставляет плейсхолдеры рисунков | после research/calc, до humanizer |
| humanizer-agent | очеловечивание, факт-замок, эм-деши ≤ 3–5 % | всегда после draft, до norm-control |
| norm-control-agent | ссылки [N], термины, ГОСТ 7.32-2017, структура документа — только помечает | перед выдачей финального текста |
| style-calibrator-agent | дифф пары → категории → порог 3+ → user-idiolect | только по «сравни черновик и мою правку» |

### Иерархия правил

При конфликте правил применяется порядок: **факт-замок** → **подтверждённый
`assets/user-idiolect.md`** (частота ≥ 3/7) → **каталог humanizer** (33
академических паттерна + русская механика) → **общие стилевые правила Projects**.

> [!NOTE]
> Границы полномочий: humanizer-agent — финальная инстанция по стилю, его
> правка не пересматривается; norm-control-agent имеет право только помечать
> ссылки и терминологический разнобой, но не переписывать стиль повторно —
> иначе конвейер «пинг-понгует» между субагентами на одном абзаце.

## Требования

- Python 3.11+ (только стандартная библиотека; нужен для evals и скриптов
  обслуживания — для работы субагентов не требуется)
- Один из поддерживаемых ИИ-инструментов (Claude Code, OpenCode и др.)

## Установка

### Claude Code (родной плагин-путь)

```bash
/plugin marketplace add ./academic-writing-suite
/plugin install academic-writing-suite
```

### Остальные платформы (универсальный установщик)

```bash
./academic-writing-suite/install.sh                # автоопределение платформы, user-level
./academic-writing-suite/install.sh --project      # project-level (текущая директория)
./academic-writing-suite/install.sh --platform opencode --path ~/.config/opencode/skills/
./academic-writing-suite/install.sh --all          # установить во все обнаруженные инструменты
./academic-writing-suite/install.sh --dry-run      # предпросмотр без изменений
```

### Вручную

| Платформа | Путь |
|---|---|
| Claude Code | `~/.claude/skills/academic-writing-suite/` |
| OpenCode | `~/.config/opencode/skills/academic-writing-suite/` |
| Codex / универсальный | `~/.agents/skills/academic-writing-suite/` |
| Gemini CLI | `~/.gemini/skills/academic-writing-suite/` |
| Cursor (адаптация `.mdc`) | `~/.cursor/rules/academic-writing-suite.mdc` |

Скопируйте содержимое `academic-writing-suite/` (SKILL.md, AGENTS.md, skills/,
shared/, assets/, references/, evals/, .claude-plugin/) в выбранный путь.

## Использование

```
/academic-writing-suite напиши раздел 2.1.1 Постановка задачи формализации
/academic-writing-suite напиши главу 2
/academic-writing-suite напиши весь диплом
/academic-writing-suite проверь текст на AI-маркеры
/academic-writing-suite рассчитай межпоездной интервал
/academic-writing-suite сравни черновик и мою правку
```

> [!TIP]
> Перед полным развёртыванием прогоните архитектуру на 2–3 реальных разделах
> ВКР: конвейер увеличивает число вызовов модели на раздел, а рассинхронизация
> форматов между шагами (например, calc-agent вернёт цифру без единиц
> измерения) ломает следующий шаг.

## Калибровка идиолекта (для автора)

Функция только для владельца репозитория: агент учится на ручных правках
автора. Рядовому пользователю этот цикл не нужен — достаточно seed-правил из
`academic-writing-suite/assets/user-idiolect.md`.

1. draft-agent пишет черновик, автор вручную правит текст.
2. Автор запускает «сравни черновик и мою правку» — style-calibrator-agent
   строит дифф по предложениям (`shared/diff_texts.py`), классифицирует правки.
3. Правила, повторившиеся ≥ 3 раз из 7 проверок, попадают в
   `assets/user-idiolect.md` и становятся обязательными для draft-agent.

Рабочие данные цикла живут в `style-calibration/` (edit-log, отчёты, рабочая
копия идиолекта) — они gitignored.

## Тестирование и обслуживание

Из папки `academic-writing-suite/`:

```bash
python3 scripts/run_evals.py --validate        # проверить спецификацию (должна быть VALID)
python3 scripts/run_evals.py                   # command-чеки по golden-бейзлайну
python3 scripts/run_evals.py --rollout --judge # judge-чеки (связность, тон) с канарейкой
python3 scripts/evolve.py                      # staleness + evals одним запуском
python3 scripts/evolve.py --correct "<что пошло не так>"  # зафиксировать правку в EVOLUTION.md
```

Состояние: 36/36 command-чеков зелёные (9 чеков × 4 val-кейса), case-5 —
holdout (9 skipped), case-6 — полнодокументный режим с плейсхолдерами рисунков.
